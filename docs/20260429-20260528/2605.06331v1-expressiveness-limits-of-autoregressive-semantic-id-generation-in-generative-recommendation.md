## 摘要
生成式推荐（GR）模型通过自回归地生成一系列离散标记来索引目标物品，从而生成物品。然而，这种自回归生成过程也引入了一个结构化的解码空间，其对模型表达能力的影响尚未得到充分探索。具体而言，逐标记生成可被视为遍历由语义ID标记所诱导的解码树，其中叶节点对应候选项。我们观察到，GR模型产生的物品概率与该树结构强相关：树中相近的物品对于任何给定用户往往获得相似的概率，使得难以根据用户特定偏好区分它们。我们进一步从理论上证明，这种结构相关性使得GR模型甚至无法表示那些能被传统协同过滤模型良好捕捉的简单模式。为缓解这一问题，我们提出Latte，一种简单的改进方法，即在每个语义ID之前注入一个潜在标记，将解码空间从单棵树重塑为多棵以潜在标记为条件的树。该设计创造了物品之间具有不同树距离的多条路径，放松了由树结构引起的概率耦合，在NDCG@10上平均相对提升3.45%。我们的代码可于https://github.com/hyp1231/Latte获取。

## Abstract
Generative recommendation (GR) models generate items by autoregressively producing a sequence of discrete tokens that jointly index the target item. However, this autoregressive generation process also induces a structured decoding space whose impact on model expressiveness remains underexplored. Specifically, token-by-token generation can be viewed as traversing a decoding tree induced by semantic ID tokens, where leaf nodes correspond to candidate items. We observe that the item probabilities produced by GR models are strongly correlated with this tree structure: items that are close in the tree tend to receive similar probabilities for any given user, making it difficult to distinguish among them based on user-specific preferences. We further show theoretically that such structural correlations prevent GR models from representing even simple patterns that can be well captured by conventional collaborative filtering models. To mitigate this issue, we propose Latte, a simple modification that injects a latent token before each semantic ID, reshaping the decoding space from a single tree into multiple latent-token-conditioned trees. This design creates multiple paths with varying tree distances between items, relaxing tree-induced probability coupling and yielding an average of 3.45% relative improvement on NDCG@10. Our code is available at https://github.com/hyp1231/Latte.

### 1. 论文的核心问题与整体含义

- **研究动机与背景**：生成式推荐（Generative Recommendation, GR）通过自回归生成离散语义 ID（Semantic ID, SID）来索引物品，但其逐 token 生成过程可视为在由有效 SID 构成的解码树上遍历。
- **核心问题**：这种树结构导致“物质概率强相关”——树距离近的物品（共享长前缀）对任意用户都会获得高度相似的生成概率。这使得模型难以表达个性化的偏好反转（如用户 A 喜欢物品甲、用户 B 喜欢物品乙），也迫使物品相似性满足传递性（即若甲与乙相似、乙与丙相似，则甲必须与丙相似），而现实世界中这可能不成立。
- **整体含义**：该研究首次从表达能力的角度，揭示了自回归语义 ID 生成的固有限制，为理解和改进生成式推荐提供了新的理论视角。

### 2. 论文提出的方法论

- **核心思想**：通过在现有语义 ID 序列前植入一个额外的“潜在 token”（latent token），将原本单一的固定解码树重构为多棵以潜在 token 为条件的子树，从而为物品间提供多种树距离路径，松弛原有结构中强制的概率耦合。
- **关键技术细节**：
  - **训练阶段**：从一个小规模的潜在 token 词汇表 \(\mathcal{L}\) 中随机采样一个潜在 token \(\ell\)，将其拼接到目标 SID 序列前，形成新的优化目标 \((\ell, c^{(1)}_t, c^{(2)}_t, \dots, c^{(m)}_t)\)，并使用标准下一 token 预测损失训练。
  - **推理阶段**：模型自回归地首先生成潜在 token，再继续生成 SID token；物品概率重定义为 \(P(i_t | u) = \text{Agg}_{\ell \in \mathcal{L}} \left( P(\ell|u) \prod_{j=1}^{m} P(c_t^{(j)} | \ell, c_t^{(1:j-1)}, u) \right)\)，其中 Agg 为 sum 或 max 聚合，实践中用束搜索近似。
  - **动态树距离**：不同物品若被分配不同潜在 token，其有效树距离变为 \(2(m+1)\)（极大值），从而让原本树距离近的 items 在概率计算早期即解耦，降低相关性。
- **算法流程（文字说明）**：
  1. 设定潜在 token 集合大小 \(M' \ll M\)。
  2. 训练时对每个目标 SID 随机采样潜在 token，拼接后作为解码目标。
  3. 推理时采用单次束搜索，首先生成潜在 token，再依束搜索生成剩余 SID token，最后对同一物品的不同路径概率进行聚合。

### 8. 不足与局限

- **额外推理开销**：尽管仅增加一个解码步骤，但在延迟敏感的在线系统中仍可能产生影响。
- **潜在退化风险**：若不同潜在 token 学得相似嵌入，Latte 可能退化为基础模型；极端情况下不同条件路径可能产生相近概率分布，削弱解耦效果。
- **不完全解耦**：在同一潜在 token 路径内部，物品仍会共享前缀并保留一定程度的概率耦合。
- **潜在 token 设计非最优**：作者明确表示 Latte 仅是缓解问题的一种简单示例，并非根本性解决方案，更优的解码结构仍有待探索。
- **实验局限**：主要在 Amazon 类别数据集和中型生成模型上验证，大规模工业场景的适用性尚需进一步检验；多模态实验仅针对一种特定偏置（模态排列），其他归纳偏置的泛化能力未深入考察。
