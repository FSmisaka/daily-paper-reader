## 摘要
基于大语言模型（LLM）的生成式列表推荐已取得快速进展，但解码仍依赖顺序生成，易导致高延迟。为在不改变目标分布的前提下加速推理，推测解码（SD）使用一个小型草稿模型一次性提议多个后续词元，再由目标LLM验证并接受最长前缀，每轮可跳过多个步骤。然而，在生成式推荐中，每个物品由多个语义ID词元表示（常带分隔符），当前草稿方法通常统一处理这些词元，忽视了两种实际情况：(i) 词元的语义取决于其在物品内的位置，(ii) 不确定性随推测深度增加而上升。若不对这些效应建模，SD的加速效果会受到限制。为此，我们提出PAD-Rec，即面向生成式推荐的位置感知草稿方法，这是一个轻量级模块，通过两种互补信号增强草稿模型：物品位置嵌入显式编码每个词元在物品内的位置，增强结构感知；步骤位置嵌入编码当前草稿步数，使模型能够适应深度相关的不确定性并提升提案质量。为将这些信号与基础特征协调，我们添加了简单门控——针对物品位置的可学习系数和针对草稿步数的上下文驱动门控。该模块可训练，易于集成至标准草稿模型，且推理开销可忽略。在四个真实数据集上的大量实验表明，相较于强SD基线，方法实现了最高3.1倍的墙钟时间加速和约5%的平均加速增益，同时大幅保持了推荐质量。

## Abstract
Large language model (LLM)-based generative list-wise recommendation has advanced rapidly, but decoding remains sequential and thus latency-prone. To accelerate inference without changing the target distribution, speculative decoding (SD) uses a small draft model to propose several next tokens at once and a target LLM to verify and accept the longest prefix, skipping multiple steps per round. In generative recommendation, however, each item is represented by multiple semantic-ID tokens, often with separators, and current drafts typically treat these tokens uniformly. This overlooks two practical facts: (i) a token's semantics depend on its within-item slot, and (ii) uncertainty tends to increase with speculation depth. Without modeling these effects, SD's speedups can be limited. We introduce PAD-Rec, Position-Aware Drafting for generative Recommendation, a lightweight module that augments the draft model with two complementary signals. Item position embeddings explicitly encode the within-item slot of each token, strengthening structural awareness. Step position embeddings encode the draft step, allowing the model to adapt to depth-dependent uncertainty and improve proposal quality. To harmonize these signals with base features, we add simple gates: a learnable coefficient for item slots and a context-driven gate for draft steps. The module is trainable, easy to integrate with standard draft models, and adds negligible inference overhead. Extensive experiments on four real-world datasets show up to 3.1x wall-clock speedup and about 5% average wall-clock speedup gain over strong SD baselines, while largely preserving recommendation quality.

### 1. 论文的核心问题与整体含义

*   **研究背景：** 基于大语言模型的生成式列表推荐发展迅速，但其自回归解码过程（逐个词元生成）具有顺序性，导致推理延迟高，难以满足实时推荐场景的需求。
*   **核心问题：** 现有的无损加速技术，即**推测解码**，虽然通过“小模型提议、大模型验证”的方式减少了目标大模型调用次数，但直接应用于推荐任务时存在两个未被解决的任务特异性问题：
    *   **忽视词元的槽位语义：** 推荐系统中，每个物品被表示为固定序列的语义ID词元（如4个）。这些词元的语义依赖于其在物品内的固定槽位（Slot），而现有草稿模型统一对待所有词元，未能利用这种结构信息，削弱了建模和对齐能力。
    *   **忽视深度驱动的不确定性：** 随着草稿步骤加深，由于依赖链变长和误差累积，词元的不确定性增加，更容易被验证阶段提早拒绝。现有方法大多是“步骤无关”的，草稿模型无法根据推测深度自适应调整提案策略，导致深层提案接受率低。
*   **整体含义：** 为生成式推荐系统设计结构感知的推测解码方法，是提升推理效率、降低延迟的有效路径，这对于推动大语言模型在实时推荐场景中的落地应用具有重要意义。

### 2. 论文提出的方法论

PAD-Rec是一个可训练的轻量级模块，可轻松集成到标准草稿模型（如HASS、EAGLE）中，通过注入两类位置信号并辅以门控机制来增强草稿质量。

*   **核心思想：** 让草稿模型明确感知两个维度的位置信息，以生成更高质量、更易被接受的提案。
    *   **第一个维度 (结构感知):** 词元在其所属物品内的槽位 (`within-item slot`)。
    *   **第二个维度 (深度感知):** 当前词元处于推测解码的第几步 (`draft step`).

*   **关键技术细节：**
    1.  **物品位置嵌入 (Item Position Embeddings, IPE):**
        *   为每个词元分配一个槽位标签 ℓₜ（例如，1到K代表语义ID的K个层级，`sep`代表分隔符，`ctx`代表指令/上下文词元）。
        *   通过一个轻量级的嵌入表 `Emb_item(·)` 查询得到 `vₜ = Emb_item(ℓₜ)`，并注入到词元嵌入中，以加强结构感知。
    2.  **步位置嵌入 (Step Position Embeddings, SPE):**
        *   为当前草稿步骤深度`j`索引一个轻量级嵌入表 `Emb_step(·)`，得到 `sⱼ = Emb_step(j)`。
        *   注入此信息使模型能学习到深度依赖的行为（如随深度增加调整置信度）。
    3.  **门控融合 (Gating Mechanisms):**
        *   **槽位感知融合（第一阶段）:** 将词元嵌入`eₜ`与经可学习标量系数 `g_item` 调制的IPE `vₜ`相加，然后与上一步的草稿特征`f_{t-1}`拼接。`f'_{t-1} = concat(eₜ + g_item · vₜ, f_{t-1})`。通过一个可学习的标量`g_item ∈ [0,1]`来控制槽位信号的总体强度。
        *   **深度感知融合（第二阶段）:** 将拼接后的特征投影回原始维度 `z_{t-1} = FC(f'_{t-1})`，再与经上下文驱动门控`g_step(t)`调制的SPE `sⱼ`相加，得到当前步的草稿特征。`fₜ = z_{t-1} + g_step(t) · sⱼ`。
        *   **上下文驱动步门控:** `g_step(t) = σ(wᵀz_{t-1})`，其中`σ`是Sigmoid函数，`w`是学习的向量。此设计允许模型根据当前草稿上下文动态调整深度信息的影响，在不确定性高时增强深度信号。

*   **算法流程：**
    1.  **训练:** 采用HASS风格的多步对齐蒸馏训练。对草稿深度`j`从1到`B`（最大推测深度），使用因果掩码和渐进式替换（将教师模型特征逐步替换为浅层草稿特征），蒸馏目标大模型在响应位置上的分布，并加入`Aux-loss`。同时训练草稿层、IPE/SPE嵌入表及门控参数。
    2.  **推理:** 草稿模型根据当前词元的槽位和推测步数，获取IPE和SPE，生成候选词元树（最大深度`B`）。目标大模型在一个批次内验证所有候选，接受最长匹配前缀，从而一次推进多个词元。
